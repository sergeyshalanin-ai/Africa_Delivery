ADR 2 Стратегия кэширования
Дата: 18 августа 2026 года
Статус: Accepted

Контекст
Africa Delivery запускает маркетплейс в Нигерии и Кении с целевой датой 15 октября. В первые 72 часа после запуска ожидается рекламный пик: до 5 000 одновременных пользователей и до 500 RPS на критические API. При этом бюджет CFO ограничивает регулярные технические расходы суммой $5 000 в месяц, а команда ограничена шестью контракторами до декабря.

Без кеширования каждый просмотр каталога, карточки товара, категории и поисковой выдачи будет обращаться к PostgreSQL. Это создаст риск деградации производительности, перегрузки БД, роста стоимости инфраструктуры и нарушения SLO:
1. p95 API каталога и поиска ≤ 500 мс;
2. время до первого товара ≤ 2 секунды;
3. доступность критического пути ≥ 99,9%;
4. поддержка роста каталога до 50 000 SKU.
Необходимо выбрать стратегию кеширования, которая ускорит чтение, защитит БД от пикового трафика и не создаст избыточной эксплуатационной сложности.

Рассмотренные варианты: 
Без кэша
Суть: Все запросы читают из БД PostgreSQL.
Преимущества: Простота, нт проблем инвалидации
Ограничения: Высокая нагрузка на БД, риск нарушения latency SLO и дорогое масштабирование

Redis cache - для горячих данных
Суть: Приложение сначала проверяет данные в кэше, если не находит ищет в PostgreSQL
Преимущества: Увеличение быстродействия, снижает нагрузку на БД, идеально подходит для MVP
Ограничения: Необходим TTL и инвалидация

Полное кэширование в redis
Суть: Все данные кэшируются 
Преимущества: Максимальная скорость чтения
Ограничения: Высокий риск устаревания данных

Решение: 
Исползование redis-cashe для горячих данных каталога, категории, карточек товаров и поисковых подсказок

Какие данные кэшируются: 
Карточка товара - Redis - TTL = 5-15 минут - Стратегия инвалидации: При изменении товара - данные из редиса удаляются
Категории и древо категорий - Redis - TTL = 1-6 часов - Стратегия инвалидации: при изменении категории - данные из редиса удаляются
Популярные товары - Redis - TTL = 5-15 минут - Стратегия инвалидации: TTL + периодическое обновление
Результаты популярных поисковых запросов - Redis - TTL = 1-5 минут - Стратегия инвалидации: TTL
Корзина гостя - TTL = 24 часа - Стратегия инвалидации: TTL 
Цена и наличие товара - TTL = 30-60 секунд - Стратегия инвалидации: при изменении цены или товара - данные из редис удаляются
Заказы - не кэшируются
Платежи и выплаты - не кэшируются
Статусы доставки - не кэшируются
Перс данные - не кэшируются

Обоснование
Кэшированние определенных сущностей необходимо чтобы выполнить НФТ по производительности и масштабируемости: 
1. p95 API каталога и поиска ≤ 500 мс;
2. время до первого товара ≤ 2 секунды;
3. поддержка пика до 5 000 одновременных пользователей;
4. поддержка до 50 000 SKU;
5. защита PostgreSQL от рекламного пика.
